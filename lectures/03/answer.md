# 第3回 解答


## 演習

### 1. 第1回のLLMとエージェントの回答比較

質問：
AIE2026の講座の宿題にある「3レベル」とは何ですか？

通常のLLM（app.ask）：
講座固有の定義を確認できず、AIの自律性、プロンプトエンジニアリングの習熟度、宿題の難易度という3種類の解釈を提示した。宿題の難易度についても「基礎・応用・発展」と説明しており、講座の正確な定義とは異なった。

エージェント（app.agent）：
search_glossaryで用語集を検索し、「基礎（講義内容の確認）」「実装（自分でコードを書く）」「発展（調査や試行）」と正しく回答した。

### 2. ツール呼び出しの確認

3レベルについての質問：
- ツール：search_glossary
- 引数：{"query": "3レベル"}
- LLM呼び出し：2回
- ツール呼び出し：1回

第2回の確認問題を生成する質問：
- ツール：make_quiz
- 引数：{"lecture": 2}
- LLM呼び出し：2回
- ツール呼び出し：1回
- 生成された問題：「ランク（LoRAのr）」の意味は？

### 3. 追加したツール

make_quiz(lecture: int)をapp/tools.pyに実装し、app/agent.pyのagent.tool_plainで登録した。

指定した講義回の用語をload_glossaryから抽出し、random.choiceで1つを選択して、問題と答えをJSON形式で返す。無効な講義回や用語が見つからない場合はエラー情報を返す。

docstringには、指定回の用語から復習問題を生成する目的と、「第2回の確認問題を出して」のような利用場面を明記した。

### 4. テスト結果と考察

- --list-toolsでmake_quizを含む3つのツールを確認した。
- make_quiz(2)を直接呼び出し、JSON形式の問題生成を確認した。
- Geminiによる実行でmake_quizの自動呼び出しを確認した。
- uv run pytest -qで23件すべてのテストが通過した。

通常のLLMは講座固有の情報を推測で補完した。一方、エージェントは外部の用語集を参照できるため、根拠に沿った回答を生成できた。ただし、ツールで取得した情報以外の補足が常に正確とは限らないため、最終回答の検証も重要だと分かった。

### やったこと

学習した内容を learning_log/ フォルダへ保存する
save_learning_log ツールを実装した。

app/lesson03_tools.py に保存処理を実装し、

app/agent.py では保存専用の save_agent を用意し、
requires_approval=True でツールを登録した。

また、output_type に DeferredToolRequests を指定し、
保存要求が発生した場合に処理を一時停止するようにした。

CLIには --save-log オプションを追加した。
利用者が保存内容を確認し、yes または no を入力すると、
DeferredToolResults を渡してエージェントを再開する。

通常の学習支援エージェントは別に維持し、
既存の用語検索・講義要約・クイズ生成機能との
干渉を避けた。

### 気づき・疑問

最初はGeminiが保存ツールを呼び出さず、
文章で承認を求めて終了する場合があった。

モデルへの指示だけではツールの呼び出しを
常に保証できないことが分かった。

また、承認付きツールを通常のエージェントに追加すると、
既存テストが想定する即時実行と衝突した。

そこで保存専用エージェントを分離し、
保存前の承認をプログラム側で制御した。

この実験から、モデルによる判断と、
ハーネスによる権限・実行制御を区別する重要性を学んだ。
